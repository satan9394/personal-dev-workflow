# Git 历史考古

## 角色与目标
你负责读这个仓库的历史，分清哪些设计是有意为之、哪些是历史遗留、哪些是为了解决已经不存在的问题而引入的。不要只看当前文件，也不要把旧东西一律当成垃圾。

## 输入
`$ARGUMENTS` = 想考古的模块、文件或时间段。若为空，默认覆盖整个仓库的 live tree，并把重点放在 `skills/`、`scripts/`、`DEPLOYMENT.md`、`RELEASING.md` 与 `.opencode/`。

## 硬约束
- 只读：不改文件、不 git add/commit/push、不重置/清理/切分支。
- 证据：每个判断给 commit hash、`file:line` 或命令输出；没有证据的标“推断”。
- `archive/`、历史 tag、旧代际副本是刻意保留的可回溯材料，不列入“可删除”。
- Skill 本体的新能力必须先上游、再适配；不在本仓库反向补丁。
- 中文；先结论后依据。

## 步骤
1. 建时间线：
   - `git log --oneline --decorate -40`
   - `git log --stat -- <路径>` 看关键路径的变更密度
   - `git log -S "<关键词>" --oneline` 追某个概念的出现/退场
2. 找关键转折：v1.0.0 双 skill、v2.0.0 插件/派生副本移除、1.3.3 多次就地重切、1.4.0-local、2026-11-17 junction 修复与分发链改口径。
3. 把发现分成四类：
   - 有意设计：现在仍有明确目的，附证据；
   - 历史遗留：当时合理、现在代价大于收益；
   - 为解决已不存在的问题而引入：问题已消失，机制还在；
   - 文档残留：代码已变，文档还停在旧口径。
4. 对每个“可移除/可简化”候选给：证据、调用路径、移除风险、必须保留的理由（若有）。
5. 不要删除、不要改写历史。

## 输出
- 结论：一句话说历史包袱主要在哪。
- 时间线：关键提交与它们改变了什么。
- 分类表：四类，逐条带证据。
- 可安全简化候选：按收益/风险排序；每条写验证方式。
- 必须保留：明确列出，防止后续误删。

## 停止条件
只报告，不改历史、不删文件。发现需要上游先改的能力，明确指出并停止。
