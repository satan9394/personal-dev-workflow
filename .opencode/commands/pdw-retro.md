# 返工复盘

## 角色与目标
你负责复盘最近一段时间的 Bug、返工、回滚和重复修改，找共同根因，并判断哪些能沉淀成项目规则、校验脚本或命令。不要只统计“发生了什么”，也不要为了凑结论把无关问题硬归成一类。

## 输入
`$ARGUMENTS` = 时间窗（如 `90d`、`30d`、`2026-10-01..2026-11-17`）。若为空，默认最近 90 天。

## 硬约束
- 只读：不改文件、不 git add/commit/push、不重置/清理。
- 证据：每个返工模式给 commit hash、CHANGELOG 条目、`file:line` 或命令输出。
- 区分“真实返工”和“正常迭代”；没有证据的重复不算模式。
- `archive/` 是刻意保留的历史，不作为当前问题来源。
- 中文；先结论后依据。

## 步骤
1. 取证：
   - `git log --since="<时间窗>" --oneline --decorate`
   - `git log --since="<时间窗>" --grep="fix\|revert\|recut\|重切\|修复\|回滚" --oneline`
   - 读 `CHANGELOG.md` 对应条目
   - 读 `.pdw/HANDOFF-*.md` 与 `.pdw/skill-adaptation-*/` 里的交接，找“差点回滚/重复修/口径变化”
2. 找重复模式：同一问题修多次、同一文件反复改、同一口径在多个文档里反复漂移、同版本号多次重切、修完又回滚。
3. 对每个模式追根因：流程缺口、校验缺口、单一事实源缺失、上下文丢失、平台差异、文档未随代码更新。
4. 判断可沉淀形式：
   - 规则：写进 `AGENTS.md` 或项目约定；
   - 校验：加到 `scripts/validate-skills.mjs`、`verify-distribution.mjs` 或新的只读检查；
   - 命令：落成 `.opencode/commands/pdw-*.md`；
   - Skill：必须上游先行，不在本仓库反向补丁。
5. 给优先级和验证方式；不要实施。

## 输出
- 结论：一句话说最贵的返工根因。
- 返工模式：模式、证据、重复次数、影响。
- 根因：按“流程/校验/事实源/上下文/平台”分类。
- 沉淀建议：规则/校验/命令/Skill，附优先级、风险、验证方式。
- 不建议沉淀：明确列出，防止过度自动化。

## 停止条件
只复盘，不改代码或规则。需要上游先改的，明确指出。
